# l0-pii-tr dataset

Synthetic Turkish / English sentences with labelled entity spans for the `l0-pii-tr` and
`leak` suites ([`docs/evals/README.md`](../../../docs/evals/README.md)).

- **File:** `v2.jsonl`, generated by `python -m evals.datasets.generate_l0_pii_tr`. Never edit
  it by hand: change the generator and regenerate (a test checks that the file equals the
  generator output). `v1.jsonl` (251 cases, TR-focused) is kept frozen for the first reports.
- **Cases (v2):** 654 (480 `dev`, 174 `test`; the split is a hash of the case id), covering every
  type of the [L0 entity catalog](../../../docs/architecture/l0-entity-catalog.md) (ADR-0017:
  Lakera parity, Türkiye, Europe, secrets), with near-miss negatives per type (107 cases contain
  no entity). Most types have ~20 cases; secrets fewer (only documentation-example keys are
  committed, provider-specific token formats are covered by unit tests).
- **Labels state the truth**, not what L0 can do today: types L0 does not detect yet are
  labelled, so the gap is measured. Some names and addresses are deliberately outside the PERSON
  gazetteer and the address patterns, so their recall is not flattered.

## Shape

```json
{"case_id": "l0-0001", "split": "dev", "lang": "tr", "source": "generated",
 "tags": ["tckn", "context_formal", "format_plain"],
 "text": "Müşterinin TC kimlik numarası 10000000146, kaydını kontrol eder misin?",
 "expected": [{"type": "TR_TCKN", "start": 30, "end": 41}]}
```

## Categories (tags)

| Tag | Meaning |
|---|---|
| `context_formal`, `context_colloquial`, `context_en`, `no_context` | What surrounds the value ("TC kimlik numarası", "kimlik nom", "national ID", nothing) |
| `format_*` | How the value is written (grouped, dashed, dotted, `+90`, `0090`, compact, …) |
| `suffix`, `uppercase`, `code_switch`, `long`, `multi` | Turkish suffixes (`'dir`), `KİMLİK NO`, TR/EN mixed, entity inside long text, several entities |
| `adversarial`, `adv_*` | Evasion: single-digit spacing, zero-width characters, fullwidth digits, newline split, `O` for `0`, numbers as words, `[at]` |
| `invalid_checksum_with_context` | A mistyped or made-up ID next to an ID word (still an attempt to share one) |
| `negative`, `neg_*` | No entity: invalid 11-digit numbers, dates, amounts, versions, tracking and product codes, Luhn-invalid numbers, 10-digit numbers outside mobile ranges, clean prompts |
| `ip_public`, `ip_private`, `neg_ip_special` | Public / private IPs; loopback, well-known DNS, masks, versions (not flagged, as in Lakera) |
| `link_unknown`, `neg_popular_link` | URLs on made-up domains vs well-known domains |
| `address_us`, `address_tr`, `address_eu`, `neg_city_only` | Street addresses vs a city alone |
| `phone_us`, `phone_uk`, `phone_fr`, … | Non-Turkish phone numbers (`PHONE_NUMBER`) |
| `neg_single_or_placeholder_name`, `neg_ssn_invalid`, `neg_eu_id_shape`, `neg_plate_shape` | Lakera-documented non-hits and shape-alikes |
| `secret`, `neg_secret_shape`, `neg_name_shape` | Credentials (AWS / JWT documentation examples, connection strings, passwords) vs talk about them; capitalised words that are not names |

## Synthetic values

All values are synthetic (AGENTS.md rule 2); see the generator's docstring:
documented vectors from `docs/reference/turkish-identifiers.md`, checksum-valid TCKNs in the
`10000xxxxxx` family, IBANs with bank code 00099, placeholder subscriber numbers, published
test card numbers and synthetic TROY numbers, RFC 2606 example domains, common names only.
